# TicketFlow 管理端操作手册

适用对象：系统管理员及处理团队负责人。版本：2026-10-21 分析与登录保持版。

## 1. 首次登录与日常入口

访问 https://8.159.144.194/ticketflow/ ，用单独交付的管理员账号登录。首次登录后进入“个人设置”修改初始密码，日常使用实名账号。“保持登录30天”适用于个人电脑，公共电脑请取消并主动退出。退出或修改密码会使该账号所有现有会话失效；停用账号也会立即阻止旧会话继续访问。

管理员拥有全局工单与报表权限，请妥善保管账号。当前系统没有邮箱找回密码和完整管理审计，忘记管理员密码需联系系统维护人员处理。

## 2. 处理组和账号管理

进入“账号与处理组”。先创建处理组，例如ERP支持、基础设施，再创建处理人账号并加入对应组。账号角色：申请人提交和验收自己的工单；处理人可处理自己提交、分派给自己以及所属处理组的工单；管理员可管理全局。

新注册账号进入待审核状态。核对姓名、用途和所属团队后，审核启用；注册默认是申请人，不能自行提升权限。账号列表支持搜索，管理员可维护姓名、处理组以及启停状态。当前界面没有任意修改已有账号角色的入口；创建账号时请选对角色。系统禁止停用当前管理员自身账号，避免误锁。

暂离人员可停用账号。修改权限或团队前先检查其负责工单是否需要转派；团队变更会影响可见范围。

## 3. 受理、分派与流转

在“工单中心”筛选待受理或紧急工单。打开详情，核对类型、优先级、内容及附件。分派处理人时只选择当前组内已启用的处理人或管理员。

转处理组时必须填写原因，系统会清空原处理人，需重新分派。状态通常为待受理→处理中→待确认→已关闭。处理完成后写明解决方案再提交待确认，由申请人验收；管理员也可按实际情况完成流转。

从待确认退回、已关闭重新打开或管理员取消工单，必须填写原因。取消后不能继续流转，操作前核实。内部备注仅处理团队和管理员可见，普通申请人看不到；附件没有单独的内部权限，工单可见者均可下载。

## 4. 分析与报表：选择范围

点击管理员专属的“分析与报表”。默认近30天，可点击近7天、近30天或近90天，也可指定日期，最长366天。日期按北京时间的工单创建日期计算，起止日期均包含。

可叠加当前状态、工单类型、优先级、处理组和处理人。处理组“未分配”筛选没有组的工单；处理人“未分派”筛选没有处理人的工单。选择条件后点击“应用筛选”。条件尚未应用时页面会提示，导出仍使用上一次成功加载的范围，避免图表与文件不一致。

例：选择本月、ERP问题、ERP支持组并应用，可了解该批工单的当前状态、优先级和处理人分布。再选择紧急可检查重点工单。清除单个条件后再次应用即可扩大范围。

## 5. 指标和图表口径

工单总数：筛选范围内所有工单，包括已取消。

当前未关闭：待受理＋处理中＋待确认，不含已关闭和已取消。

当前关闭率：范围内当前已关闭数÷范围内总数；无数据时为0%。这不是当期结案率，也不是SLA达标率。

未分派且未关闭：当前处理人为空，且处于待受理、处理中或待确认。

紧急且未关闭：优先级为紧急，且处于上述三个未关闭状态。

每日新增趋势按创建日期统计，零工单日期补0。状态、优先级、类型、处理组和处理人图表展示当前字段值；处理组或处理人发生变化后，统计随之变化。条形图最多显示前12项，完整分组可在汇总CSV查看。当前版本没有历史时点快照、平均解决时长、SLA或自定义公式。

## 6. 导出报表和图表

“导出汇总 CSV”包含筛选日期、指标、各维度完整分组及每日新增数据。“导出明细 CSV”包含工单编号、标题、类型、优先级、当前状态、处理组、申请人、处理人、创建及更新时间；不导出正文、内部备注、附件文件或密码。

CSV使用UTF-8带BOM，可由Excel等工具打开；标题和姓名等文本若以公式字符开头，会添加保护前缀，防止作为公式执行。明细最多10,000行，超过时系统拒绝导出，请缩小日期或筛选范围；不会静默截断。汇总和明细使用同一组已应用筛选，但不同导出请求之间如有他人修改数据，结果可能随最新状态变化。

每张图表右上角“导出 PNG”可下载图片，适合报告和演示。图片包含图表标题与数据；图表标题包含日期范围，分享时也应注明筛选条件。报表包含业务数据，请仅向获准人员分享。管理员之外的账号不能通过接口地址下载全局报表。

## 7. 处理人日常操作

处理人登录后，在工作台或工单中心查找组内工单或分派给自己的工单，填写评论或内部备注，上传处理所需附件，推进至待确认。处理人不具备账号管理、全局分析与导出权限；取消、转处理组由管理员执行。申请人的验收步骤见用户端手册。

## 8. 备份、故障与维护

服务器每日北京时间10:15后约5分钟内自动备份数据库和附件，已有独立恢复验证。备份目前保存在同一服务器，不能防止整机损坏，后续应配置异地副本和保留策略。生产恢复由维护人员执行，管理员不要自行删除数据卷。

遇到无法登录先检查账号状态、Cookie与有效期；分析无数据先核对创建日期和叠加筛选。网络或服务器错误先刷新，持续故障时记录时间、账号和操作步骤，联系维护人员。不要提交密码、Cookie或完整登录令牌到工单。

功能边界：当前系统已具备轻分析和文件导出；通知、SLA、知识库等仍在后续范围。手册可在“操作手册”下载，本手册不替代服务器恢复方案。
